## 一、数据库选型

| 组件 | 选型 | 说明 |
|------|------|------|
| 主数据库 | PostgreSQL 16 | JSONB支持灵活字段、丰富的索引类型、异步驱动asyncpg |
| 缓存 | Redis 7 | 会话缓存、限流计数、消息队列 |
| 文件存储 | MinIO / 阿里云OSS | 图片、音频等资源文件 |

> 不使用MongoDB：对话日志存PostgreSQL即可，JSONB满足灵活字段需求。如后续分析需求增大，可引入ClickHouse做日志分析。

## 二、表结构设计

### 2.1 用户表 (users)

```sql
CREATE TABLE users (
    id              BIGSERIAL PRIMARY KEY,
    username        VARCHAR(50) NOT NULL UNIQUE,
    email           VARCHAR(255) UNIQUE,
    phone           VARCHAR(20) UNIQUE,
    password_hash   VARCHAR(255) NOT NULL,
    avatar_url      VARCHAR(500),
    preferences     JSONB DEFAULT '{}',
    status          VARCHAR(20) DEFAULT 'active',
    last_login_at   TIMESTAMPTZ,
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_email ON users(email) WHERE email IS NOT NULL;
CREATE INDEX idx_users_status ON users(status);
```

### 2.2 剧本表 (scripts)

> scripts表不再冗余存储scenes_config/characters_config，场景和角色数据由独立的scenes/characters表管理。

```sql
CREATE TABLE scripts (
    id              BIGSERIAL PRIMARY KEY,
    title           VARCHAR(200) NOT NULL,
    description     TEXT,
    genre           VARCHAR(50) NOT NULL,
    difficulty      VARCHAR(20) DEFAULT 'normal',
    author_id       BIGINT NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    cover_image     VARCHAR(500),
    banner_image    VARCHAR(500),
    setting         JSONB NOT NULL,        -- 世界观设定（低频读写，JSONB合适）
    rules           JSONB,                 -- 特殊规则
    endings         JSONB,                 -- 结局配置
    tags            VARCHAR(50)[],         -- PostgreSQL原生数组，支持GIN索引
    rating          DECIMAL(3,1) DEFAULT 0,
    rating_count    INT DEFAULT 0,         -- 评分人数，用于加权平均
    play_count      INT DEFAULT 0,
    status          VARCHAR(20) DEFAULT 'draft',
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_scripts_author ON scripts(author_id);
CREATE INDEX idx_scripts_genre ON scripts(genre);
CREATE INDEX idx_scripts_status ON scripts(status);
CREATE INDEX idx_scripts_rating ON scripts(rating DESC);
CREATE INDEX idx_scripts_play_count ON scripts(play_count DESC);
CREATE INDEX idx_scripts_created ON scripts(created_at DESC);
CREATE INDEX idx_scripts_tags ON scripts USING GIN(tags);  -- 数组索引，支持标签搜索
```

### 2.3 场景表 (scenes)

```sql
CREATE TABLE scenes (
    id              BIGSERIAL PRIMARY KEY,
    script_id       BIGINT NOT NULL REFERENCES scripts(id) ON DELETE CASCADE,
    scene_key       VARCHAR(100) NOT NULL,
    name            VARCHAR(200) NOT NULL,
    description     TEXT,
    background_image VARCHAR(500),
    background_music VARCHAR(500),
    map_data        JSONB NOT NULL,         -- 地图数据（可行走区域、障碍物、交互点等）
    connected_scenes JSONB,                 -- 连接的场景
    initial_npcs    JSONB,                  -- 初始NPC配置
    entry_conditions JSONB,                 -- 进入条件
    on_enter        JSONB,                  -- 进入事件
    on_exit         JSONB,                  -- 退出事件
    sort_order      INT DEFAULT 0,
    is_hidden       BOOLEAN DEFAULT FALSE,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_scenes_script ON scenes(script_id);
CREATE UNIQUE INDEX idx_scenes_key ON scenes(script_id, scene_key);
```

### 2.4 角色表 (characters)

```sql
CREATE TABLE characters (
    id              BIGSERIAL PRIMARY KEY,
    script_id       BIGINT NOT NULL REFERENCES scripts(id) ON DELETE CASCADE,
    character_key   VARCHAR(100) NOT NULL,
    name            VARCHAR(100) NOT NULL,
    display_name    VARCHAR(100),
    role_type       VARCHAR(50) NOT NULL,   -- protagonist/npc/antagonist
    avatar_url      VARCHAR(500),
    sprites         JSONB,                  -- 不同状态的立绘
    appearance      TEXT,
    personality     JSONB,                  -- 性格标签
    background      TEXT,
    stats           JSONB,                  -- 初始属性
    relationships   JSONB,                  -- 与其他角色的初始关系
    secrets         JSONB,                  -- 隐藏信息
    dialogue_style  TEXT,
    ai_prompt       TEXT,                   -- AI角色扮演提示词
    sort_order      INT DEFAULT 0,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

CREATE INDEX idx_characters_script ON characters(script_id);
CREATE UNIQUE INDEX idx_characters_key ON characters(script_id, character_key);
```

### 2.5 游戏会话表 (game_sessions)

> player_stats/npc_states/story_flags 使用JSONB，因为这些是高频读写的动态游戏状态，结构因剧本而异，无法预定义列。PostgreSQL的JSONB支持部分索引，可按需添加。

```sql
CREATE TABLE game_sessions (
    id              BIGSERIAL PRIMARY KEY,
    user_id         BIGINT NOT NULL REFERENCES users(id),
    script_id       BIGINT NOT NULL REFERENCES scripts(id),
    current_scene_id BIGINT REFERENCES scenes(id),
    player_name     VARCHAR(100),
    player_stats    JSONB DEFAULT '{}',
    npc_states      JSONB DEFAULT '{}',
    story_flags     JSONB DEFAULT '{}',
    game_phase      VARCHAR(50),
    game_time       VARCHAR(100),
    alive_count     INT DEFAULT 0,
    status          VARCHAR(20) DEFAULT 'active',
    current_ending  VARCHAR(100),
    created_at      TIMESTAMPTZ DEFAULT NOW(),
    updated_at      TIMESTAMPTZ DEFAULT NOW(),
    completed_at    TIMESTAMPTZ
);

CREATE INDEX idx_sessions_user ON game_sessions(user_id);
CREATE INDEX idx_sessions_script ON game_sessions(script_id);
CREATE INDEX idx_sessions_status ON game_sessions(status);
CREATE INDEX idx_sessions_created ON game_sessions(created_at DESC);
CREATE INDEX idx_sessions_user_status ON game_sessions(user_id, status);
```

### 2.6 对话日志表 (dialog_logs)

> 这是增长最快的表。使用冷热分离策略管理。

```sql
CREATE TABLE dialog_logs (
    id              BIGSERIAL PRIMARY KEY,
    session_id      BIGINT NOT NULL REFERENCES game_sessions(id) ON DELETE CASCADE,
    scene_id        BIGINT REFERENCES scenes(id),
    character_id    BIGINT REFERENCES characters(id),
    type            VARCHAR(20) NOT NULL,   -- narration/dialog/choice/system/action
    content         TEXT NOT NULL,
    metadata        JSONB,
    player_input    TEXT,
    ai_raw_response TEXT,
    created_at      TIMESTAMPTZ DEFAULT NOW()
);

-- 关键索引：按会话+时间查询对话历史
CREATE INDEX idx_dialogs_session_time ON dialog_logs(session_id, created_at DESC);
CREATE INDEX idx_dialogs_type ON dialog_logs(type);
```

## 三、JSONB字段使用规范

| 表 | 字段 | 读写频率 | 说明 |
|------|------|----------|------|
| scripts | setting | 低频写，中频读 | 世界观设定，剧本创建后很少修改 |
| scripts | rules | 低频写，低频读 | 特殊规则 |
| scripts | endings | 低频写，低频读 | 结局配置 |
| scenes | map_data | 低频写，高频读 | 地图数据，场景编辑后很少修改 |
| game_sessions | player_stats | 高频读写 | 玩家动态属性，每轮可能更新 |
| game_sessions | npc_states | 高频读写 | NPC动态状态，每轮可能更新 |
| game_sessions | story_flags | 中频读写 | 剧情标记，关键决策时更新 |

> 原则：静态配置数据（setting、map_data等）适合JSONB；高频动态数据（player_stats等）因结构因剧本而异，JSONB是合理选择，但应控制JSON大小（建议单字段<10KB）。

## 四、dialog_logs冷热分离策略

```
┌─────────────────────────────────────────────────────────┐
│                dialog_logs 冷热分离                      │
├─────────────────────────────────────────────────────────┤
│                                                         │
│  热数据（PostgreSQL）                                   │
│  • 最近30天的对话日志                                   │
│  • 活跃游戏会话的所有日志                              │
│  • 查询：WHERE created_at > NOW() - INTERVAL '30 days'  │
│                                                         │
│  冷数据（归档策略）                                     │
│  • 超过30天且游戏已结束的日志                           │
│  • 定时任务（每天凌晨）检查并归档                       │
│  • 归档方式：                                           │
│    方案A：移动到 dialog_logs_archive 表（同结构，不同表）│
│    方案B：导出到对象存储（JSON格式），从主表删除        │
│                                                         │
│  查询适配                                               │
│  • 获取对话历史时：先查热表，不足再查归档表/存储       │
│  • 活跃会话的日志始终在热表中                           │
│                                                         │
│  预估数据量                                             │
│  • 每局游戏约100-300条对话                              │
│  • 日活1000用户，每用户1局/天 → 30万条/天              │
│  • 30天热数据约900万条，PostgreSQL完全可承受           │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

## 五、SQLAlchemy模型示例

```python
# app/models/script.py

from sqlalchemy import Column, BigInteger, String, Text, Integer, Numeric, DateTime, ForeignKey
from sqlalchemy.dialects.postgresql import JSONB, ARRAY
from sqlalchemy.orm import relationship
from app.db.base import Base

class Script(Base):
    __tablename__ = "scripts"

    id = Column(BigInteger, primary_key=True, autoincrement=True)
    title = Column(String(200), nullable=False)
    description = Column(Text)
    genre = Column(String(50), nullable=False)
    difficulty = Column(String(20), default="normal")
    author_id = Column(BigInteger, ForeignKey("users.id", ondelete="CASCADE"), nullable=False)
    cover_image = Column(String(500))
    banner_image = Column(String(500))
    setting = Column(JSONB, nullable=False)
    rules = Column(JSONB)
    endings = Column(JSONB)
    tags = Column(ARRAY(String(50)))
    rating = Column(Numeric(3, 1), default=0)
    rating_count = Column(Integer, default=0)
    play_count = Column(Integer, default=0)
    status = Column(String(20), default="draft")

    # 关系：场景和角色由独立表管理，不再冗余存储在scripts中
    scenes = relationship("Scene", back_populates="script", lazy="selectin")
    characters = relationship("Character", back_populates="script", lazy="selectin")
```

```python
# app/models/game.py

from sqlalchemy import Column, BigInteger, String, Text, Integer, ForeignKey
from sqlalchemy.dialects.postgresql import JSONB
from app.db.base import Base

class GameSession(Base):
    __tablename__ = "game_sessions"

    id = Column(BigInteger, primary_key=True, autoincrement=True)
    user_id = Column(BigInteger, ForeignKey("users.id"), nullable=False)
    script_id = Column(BigInteger, ForeignKey("scripts.id"), nullable=False)
    current_scene_id = Column(BigInteger, ForeignKey("scenes.id"))
    player_name = Column(String(100))
    player_stats = Column(JSONB, default=dict)
    npc_states = Column(JSONB, default=dict)
    story_flags = Column(JSONB, default=dict)
    game_phase = Column(String(50))
    game_time = Column(String(100))
    alive_count = Column(Integer, default=0)
    status = Column(String(20), default="active")
    current_ending = Column(String(100))

class DialogLog(Base):
    __tablename__ = "dialog_logs"

    id = Column(BigInteger, primary_key=True, autoincrement=True)
    session_id = Column(BigInteger, ForeignKey("game_sessions.id", ondelete="CASCADE"), nullable=False)
    scene_id = Column(BigInteger, ForeignKey("scenes.id"))
    character_id = Column(BigInteger, ForeignKey("characters.id"))
    type = Column(String(20), nullable=False)
    content = Column(Text, nullable=False)
    metadata = Column(JSONB)
    player_input = Column(Text)
    ai_raw_response = Column(Text)
```
