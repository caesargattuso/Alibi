## 一、需求概述

### 1.1 背景

当前游戏中的"自由行动"选项仅是一个文本输入框，玩家输入后由AI生成剧情。用户希望将其升级为**"调查"功能**：点击后加载场景地图，玩家可以在场景中移动角色、与物品交互、调查详情，也可以与场景中的NPC对话。

### 1.2 目标

- 将"自由行动"改为"调查"按钮
- 点击后进入场景探索模式（地图视图）
- 玩家可在地图上点击移动（A*寻路）
- 接近可交互点时显示交互选项
- 支持调查物品、与NPC对话
- 所有需要的图片资源使用图片生成技能生成

---

## 二、系统架构

### 2.1 整体流程

```
游戏主界面 (剧情+选项)
    │
    ▼
玩家点击"调查"按钮
    │
    ▼
切换到场景探索模式
    │
    ├── 显示场景地图 (Canvas渲染)
    ├── 显示玩家角色 (可移动)
    ├── 显示可交互点 (物品/NPC/出口)
    │
    ▼
玩家点击地图位置
    │
    ├── A*寻路计算路径
    ├── 角色沿路径移动动画
    └── 到达后检测附近交互点
    │
    ▼
接近交互点 → 显示交互菜单
    │
    ├── 调查物品 → 显示详情/获取线索
    ├── 与NPC对话 → 触发对话/获取信息
    └── 进入出口 → 切换场景
    │
    ▼
完成交互 → 返回剧情模式
    │
    ▼
AI根据交互结果生成新剧情
```

### 2.2 模块划分

| 模块 | 职责 | 位置 |
|------|------|------|
| 场景探索视图 | 地图渲染、角色移动、交互检测 | 前端新组件 |
| A*寻路引擎 | 路径计算 | 已有 `frontend/src/utils/pathfinding.ts` |
| 交互系统 | 交互点检测、交互菜单、动作执行 | 前后端 |
| 图片生成 | 场景背景、角色立绘、物品图标 | 图片生成技能 |

## 三、数据模型

### 3.1 场景数据 (Scene)

已有 `Scene` 模型包含 `map_data` JSONB 字段，需扩展以下结构：

```json
{
  "map_data": {
    "width": 1920,
    "height": 1080,
    "grid_size": 40,
    "walkable_areas": [...],
    "obstacles": [...],
    "interactable_points": [
      {
        "id": "throne",
        "name": "龙椅",
        "type": "object",
        "position": [960, 400],
        "icon": "icons/throne.png",
        "description": "皇帝的龙椅，散发着威严的气息。",
        "actions": ["examine", "touch"],
        "investigation": {
          "clue_text": "龙椅扶手上有一道细微的划痕，似乎是最近留下的。",
          "revealed_flags": ["throne_scratch_found"],
          "required_flags": []
        }
      },
      {
        "id": "npc_momo",
        "name": "教习嬷嬷",
        "type": "npc",
        "position": [960, 350],
        "npc_id": "char_momo",
        "actions": ["talk", "examine"],
        "dialogue": {
          "greeting": "你来这里做什么？",
          "topics": [
            {"id": "throne", "text": "询问龙椅", "condition": "throne_scratch_found"},
            {"id": "palace", "text": "询问宫殿", "condition": null}
          ]
        }
      }
    ],
    "spawn_points": [...]
  }
}
```

### 3.2 交互点类型

| 类型 | 说明 | 可执行动作 |
|------|------|-----------|
| `object` | 可调查物品 | examine, touch, use |
| `npc` | 可对话角色 | talk, examine |
| `exit` | 场景出口 | enter |
| `item` | 可拾取物品 | pick_up, examine |
| `container` | 可搜索容器 | search, examine |

### 3.3 交互结果

```json
{
  "success": true,
  "message": "你仔细观察龙椅...",
  "effects": [
    {"type": "set_flag", "target": "throne_examined", "value": true},
    {"type": "reveal_clue", "target": "throne_scratch", "value": "龙椅扶手上有一道细微的划痕"}
  ],
  "ai_trigger": {
    "should_generate": true,
    "context": "玩家调查了龙椅，发现了一道划痕"
  }
}
```

## 四、API设计

### 4.1 获取场景地图数据

```
GET /api/v1/scenes/{scene_id}/map
```

响应：
```json
{
  "code": 200,
  "data": {
    "width": 1920,
    "height": 1080,
    "grid_size": 40,
    "walkable_areas": [...],
    "obstacles": [...],
    "interactable_points": [...],
    "spawn_points": [...]
  }
}
```

### 4.2 执行交互动作

```
POST /api/v1/scenes/{scene_id}/interact
```

请求：
```json
{
  "session_id": 1,
  "interactable_id": "throne",
  "action_id": "examine"
}
```

响应：
```json
{
  "code": 200,
  "data": {
    "success": true,
    "message": "你仔细观察龙椅...",
    "effects": [...],
    "ai_trigger": {
      "should_generate": true,
      "context": "玩家调查了龙椅"
    }
  }
}
```

### 4.3 移动角色（前端本地计算）

角色移动使用前端A*寻路，不需要后端API。移动完成后如果触发交互，再调用交互API。

## 五、前端设计

### 5.1 场景探索视图组件

```
InvestigationView
├── SceneMap (Canvas)
│   ├── 背景图
│   ├── 可行走区域 (半透明)
│   ├── 障碍物
│   ├── 交互点图标
│   └── 玩家角色
├── InteractionMenu (Modal/Popover)
│   ├── 交互点名称
│   ├── 可用动作列表
│   └── 取消按钮
└── InvestigationLog
    └── 调查记录列表
```

### 5.2 状态管理

扩展 `gameStore` 新增调查相关状态：

```typescript
interface InvestigationState {
  isInvestigating: boolean;
  currentSceneId: number | null;
  playerPosition: { x: number; y: number };
  investigatedItems: string[]; // 已调查的物品ID
  revealedClues: string[];      // 已发现的线索
}
```

### 5.3 交互流程

1. 玩家点击"调查" → `setIsInvestigating(true)`
2. 加载当前场景地图数据 → 渲染Canvas
3. 玩家点击地图 → A*寻路 → 角色移动动画
4. 接近交互点（距离 < 50px）→ 显示交互菜单
5. 玩家选择动作 → 调用交互API
6. 显示交互结果 → 记录到调查日志
7. 点击"返回剧情" → `setIsInvestigating(false)`
8. 将调查上下文传递给AI → 生成新剧情

## 六、图片资源需求

### 6.1 需要生成的图片

| 资源 | 用途 | 尺寸 | 生成时机 |
|------|------|------|----------|
| 场景背景图 | 地图Canvas背景 | 1920x1080 | 剧本创建时 |
| 角色立绘 | NPC在地图上的形象 | 400x800 | 角色创建时 |
| 角色头像 | 对话面板 | 200x200 | 角色创建时 |
| 物品图标 | 交互点标记 | 64x64 | 物品创建时 |
| 场景缩略图 | 场景选择 | 400x225 | 场景创建时 |

### 6.2 图片生成方式

使用图片生成技能（SiliconFlow Kolors API）：

```bash
python3 ~/.claude/skills/imagexunfei/generate_image.py "<prompt>" --size <size>
```

生成后上传到MinIO存储。

## 八、与现有系统的关系

### 8.1 与剧情模式的关系

- 调查模式是剧情模式的补充，不是替代
- 调查收集的信息会影响AI生成的剧情
- 调查完成后返回剧情模式继续游戏

### 8.2 与AI服务的关系

- 调查结果通过 `ai_trigger.context` 传递给AI
- AI根据调查上下文生成相关剧情
- 可以触发新的线索、对话选项或剧情分支

### 8.3 与场景系统的关系

- 复用现有的 `Scene.map_data` 结构
- 复用 `SceneService` 的交互逻辑
- 复用 `SceneMap` Canvas组件

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 地图数据复杂 | 中 | 简化初始版本，只支持基本矩形区域 |
| 图片生成耗时 | 低 | 异步生成，先使用占位图 |
| 移动端适配 | 中 | Canvas缩放 + 触摸事件支持 |
| 性能问题 | 低 | 使用requestAnimationFrame优化 |
